# HyperFrames: как делать ролики, которые смотрят

Рабочий справочник по приёмам. Составлен по скиллам HyperFrames, каталогу из
447 готовых блоков и нашим собственным прогонам — с граблями, на которые мы
уже наступили.

Цель документа: уметь собрать захватывающий ролик и обучающее видео с
анимацией и инфографикой, не изобретая заново то, что уже написано.

---

## 1. Что такое композиция

Видео — это HTML-страница, которую движок проматывает кадр за кадром и
снимает. Отсюда всё остальное.

```html
<div id="root" data-composition-id="main" data-start="0" data-duration="20"
     data-width="1920" data-height="1080">
  <video class="clip" src="a.mp4" data-start="0" data-duration="20" data-track-index="0"></video>
  <audio id="voice" class="clip" src="v.m4a" data-start="0" data-duration="18"></audio>
  <div class="clip" data-start="2" data-duration="3" data-track-index="2">Титр</div>
</div>
<script>
  const tl = gsap.timeline({ paused: true });
  tl.fromTo("#x span", { opacity: 0 }, { opacity: 1, duration: .35 }, 2);
  window.__timelines["main"] = tl;   // ключ = data-composition-id
</script>
```

Три вещи, которые надо принять сразу:

**Одна пауза-таймлайн на композицию.** Не две, не автозапуск. Движок сам
перематывает её в нужную точку и снимает кадр.

**Длительность ролика задаёт `data-duration` корня**, а не длина таймлайна.
Таймлайн длиннее — обрежется. Короче — последний кадр замрёт.

**Каждый кадр должен быть чистой функцией времени.** Никаких `Math.random()`,
`Date.now()`, обращений к сети. Движок снимает кадры четырьмя процессами
параллельно и в произвольном порядке: всё, что зависит от «сколько прошло
с запуска», развалится.

### Что ломается молча

| Ошибка | Чем кончается |
|---|---|
| `<audio>` без `id` | рендер выходит **немым**, ошибки нет |
| GSAP не загрузился с CDN | рендер «успешен», видео **пустое** |
| CSS `transform` + GSAP-твин того же свойства | начальное состояние дерётся с твином |
| твин `visibility`/`autoAlpha` на `.clip` | движок сам владеет видимостью клипов |
| `width`/`height`/`top`/`left` в твинах | запрещены, нужны `scale`/`x`/`y` или маски |
| `<video data-start>` внутри элемента с `data-start` | не те кадры, потом клип исчезает |
| замер `getBoundingClientRect()` во время твина | рассинхрон, замеряй на старте сборки |

Первые две — самые коварные: рендер завершается «успешно».

## 2. Словарь движения: 48 атомарных приёмов

Правила лежат в скилле `hyperframes-animation`, в `rules/<имя>.md`. Берёшь
2–4 на сцену, склеиваешь одним таймлайном — этого хватает в большинстве случаев.

### Текст и типографика

| Приём | Что делает |
|---|---|
| `kinetic-beat-slam` | фразы влетают на общий бит, каждая своим способом — для ритмичных заголовков |
| `waterfall-entry` | слова входят каскадом, волной; **появление никогда не делается плавным фейдом**, только `set` 0→1 |
| `typewriter` / `discrete-text-sequence` | печать с опечатками, паузами, удалениями — живая рука, а не ровный набор |
| `gradient-text-sweep` | градиент проезжает сквозь буквы, сами буквы не двигаются |
| `hacker-flip-3d` | расшифровка: символы крутятся и подставляются по детерминированному хешу |
| `chromatic-glitch` | RGB-сдвиг с резким схлопыванием |
| `3d-text-depth-layers` | слои текста со смещением дают объёмную выдавку |
| `asr-keyword-glow` | подсветка ключевых слов **по таймкодам речи** |

### Данные и статистика — ядро инфографики

| Приём | Что делает |
|---|---|
| `stat-bars-and-fills` | столбики (`scaleY` со сдвигом), прогресс-полоса, кольцо, дробный рейтинг звёзд |
| `counting-dynamic-scale` | счётчик, который **растёт в масштабе вместе со значением** |
| `chart-scrub-readout` | курсор едет по уже нарисованному графику, тултип шагает по данным |
| `svg-path-draw` | линия графика рисует сама себя через `stroke-dashoffset` |

Правило жанра: **прибытие графика и чтение графика — разные приёмы**. Сначала
он появляется (`stat-bars-and-fills`, `svg-path-draw`), потом по нему едет
читающая голова (`chart-scrub-readout`). Смешаешь — получится каша.

### Камера

| Приём | Когда |
|---|---|
| `coordinate-target-zoom` | наезд на объект **не в центре** кадра: масштаб на внешней обёртке, встречный сдвиг на внутренней |
| `viewport-change` | виртуальная камера: весь мир в одной обёртке, `translate(x,y) scale(S)`, причём `T = -offset × S` |
| `multi-phase-camera` | отъезд → фокус → наезд плюс непрерывный микродрейф |
| `3d-camera-flight` | полёт сквозь трёхмерно разложенный мир, единственное правило с движением по Z |
| `depth-of-field-blur` | рэк-фокус: расфокус неглавных планов через `filter: blur()` |

Микродрейф — незаметное медленное движение — главное отличие живого кадра от
мёртвого. Статичный кадр дольше трёх секунд читается как стоп-кадр.

### Раскладка и сборка

`center-outward-expansion` (элементы разлетаются из центра по местам),
`grid-card-assemble` (каскадная самосборка сетки), `depth-scatter-assemble`
(разлёт и сборка в трёхмерном облаке), `orbit-3d-entry` (влёт с орбиты),
`anchored-layout-expand` (панель раскрывается, а соседи **тем же твином**
расступаются — шов не расходится), `avatar-cloud-network` (узлы с линиями к центру).

### Указатель и интерфейс — для обучающих роликов

`cursor-click-ripple` (курсор приезжает, нажимает, расходится круг),
`cursor-drag` (захват, перенос призрака, защёлкивание), `multi-cursor-choreography`
(несколько именованных курсоров работают одновременно), `press-release-spring`
и `physics-press-reaction` (тактильное нажатие), `control-target-sync`
(ползунок и то, чем он управляет, меняются **в один такт**).

### Переходы между сценами

`scale-swap-transition` (одно схлопывается, другое выскакивает с перелётом),
`card-morph-anchor` (контейнер меняет видимый размер и скругление),
`theme-crossfade-morph` (вся тема перекрашивается под неподвижным якорем),
`reactive-displacement` (входящий элемент физически выталкивает уходящий),
`nudge-curve` (медленно-быстро-медленно: группа переезжает, открывая содержимое).

### Фон и воздух

`sine-wave-loop` (дыхание), `ambient-glow-bloom` (мягкое свечение за героем,
пик прозрачности не выше ~0.45), `particle-burst` (конфетти и частицы — фиксированный
пул, баллистика как функция времени, не больше ~40 штук), `motion-blur-streak`
(смаз на быстром влёте).

## 3. Двадцать два блюпринта: готовые формы шота

Блюпринт — это **шот целиком с таймкодами**, вытащенный из 178 эталонных
роликов. Не «эффект», а расписание: что происходит на 0–2 секунде, что на 2–5.
Берут, когда нужна сцена на 4–5 фаз, а не одно движение.

| Блюпринт | Роль в ролике | Длина |
|---|---|---|
| `kinetic-type-beats` | хук, проблема, вывод — рабочая лошадка, подходит к шести ролям | 3–13 с |
| `typewriter-reveal` | хук или финал: «кто-то печатает это прямо сейчас» | 3.6–7 с |
| `dataviz-countup` | **цифра как событие** — хук, проблема, доказательство | 4–12 с |
| `spatial-pan-stations` | станции на одном большом холсте, камера едет между ними | 7–10 с |
| `camera-journey` | камера сама рассказывает причину и следствие | 5.6–11 с |
| `zoom-out-workspace-reveal` | открыть на детали, одним отъездом показать целое | 6.8–11 с |
| `grid-card-assemble` | перечислить широту: сетка, список, стена логотипов | 3–10.5 с |
| `comparison-split` | сравнение двух вариантов | 4–6 с |
| `cursor-ui-demo` | демонстрация интерфейса курсором | 4–13 с |
| `agent-progress-theater` | показ долгого процесса как спектакля | 4.2–11.6 с |
| `panel-edit-live-sync` | правка слева — результат справа в тот же такт | 5.3–11.9 с |
| `prompt-type-submit-generate` | ввод запроса → отправка → генерация | 5.2–12 с |

| `overwhelm-surround` | завал задачами — для постановки проблемы | 6–9 с |
| `titlecard-reveal` | титульная карточка | 3–5 с |
| `constellation-hub` | «всё сходится в одном центре» | 5–8 с |

| `ticker-takeover` | бегущая строка захватывает кадр | 5–7 с |

вопроса) → `dataviz-countup` или `comparison-split` (цифра, ради которой всё) →
`panel-edit-live-sync` либо `cursor-ui-demo` (как это делается) →
`grid-card-assemble` (что в итоге умеем) → `titlecard-reveal` (вывод).

## 4. Каталог: 447 готовых блоков

Не писать руками то, что уже есть. Поиск и установка:

```bash
npx hyperframes catalog "что нужно"        # поиск по смыслу
npx hyperframes add <имя>                  # ставит по одному
```

Ставится по одному имени за раз; на выходе — файл в `compositions/components/`
со сниппетом, который вставляется в композицию.

### Инфографика

`animated-bar-chart`, `bar-chart-race`, `data-chart`, `mk-line-graph`,
`decline-chart`, `chart-story` — графики.
`count-up`, `number-wheel`, `mk-progress-stat`, `conic-progress-ring`,
`star-rating-fill` — числа и прогресс.
`oscilloscope-trace` — осциллограмма.

### Схемы и процессы

`flowchart`, `flowchart-vertical`, `hw-pipeline` (**нарисованная от руки**
блок-схема — для обучающего ролика живее строгой), `exploded-stack` (разнесённый
стек слоёв), `world-map`, `us-map`, `us-map-flow`, `us-map-hex`, `spain-map`.

### Код и терминал

`code-typing` (печатается), `code-diff` (показ изменений), `code-highlight`
(подсветка нужных строк), `code-scroll` (прокрутка к строке), `code-terminal-run`
(запуск команды), `code-morph` (превращение одного кода в другой),
`code-particle-assemble` и `code-shader-dissolve` (эффектная сборка),
плюс готовые оформления окна: `code-snippet-dark-2026`, `code-snippet-apple-terminal-pro`.

### Титры — 35 стилей

`caption-editorial-emphasis` (редакционный акцент — спокойный, для нашего случая),
`caption-highlight` (маркерная подсветка), `caption-kinetic-slam` (удар),
`caption-neon-glow`, `caption-gradient-fill`, `caption-matrix-decode`,
`caption-glitch-rgb`, `caption-particle-burst`, `caption-camera-follow`,
`caption-parallax-layers`, `caption-clip-wipe`, `caption-emoji-pop`.

### Фактура и атмосфера

`vignette` (притемнение краёв), `grain-overlay` (плёночное зерно),
`organic-light-leak-overlay` (световые протечки), `aurora-drift`,
`flowing-gradient`, `yt-screen-warp` (кадр как на физическом экране),
`transitions-dissolve`, `per-word-crossfade`.

## 4б. Развернуть готовый проект целиком

Кроме отдельных блоков есть второй слой — **готовые проекты-стили**, которые
ставятся как основа:

```bash
npx hyperframes init my-video --example nyt-graph
```

Восемь кураторских шаблонов. **Их нет в каталоге блоков** — они существуют
только так, поэтому `catalog` их не покажет:

| Пример | Что это |
|---|---|
| `nyt-graph` | график в газетной манере, SVG-путь на 451 строку — эталон инфографики |
| `decision-tree` | дерево решений: узлы, ветвления, подсветка пути — основа обучающего ролика |
| `kinetic-type` | кинетическая типографика |
| `swiss-grid` | швейцарская сетка, строгая модульная вёрстка |
| `vignelli` | модернистская типографика в духе Массимо Виньелли |
| `warm-grain` | тёплая плёночная подача |
| `product-promo` | продуктовое промо |
| `play-mode` | игровая подача |

Полезнее разобрать их код, чем читать описания: это работающие композиции
на 400+ строк, из которых видно, как устроены настоящие графики и схемы.

Сверх этого `--example` принимает **любое из 447 имён каталога** — то есть
проект можно развернуть вокруг одного блока и дальше наращивать.

### Осторожно с чужими подборками

В сети ходят списки «модных шаблонов HyperFrames» с именами вроде
*Aurora Headline*, *Prism Lower Third*, *Signal Line*, *Liquid Counter*,
*BlockFrame*, *Bold Poster*, *Cobalt Grid*. Это другие проекты (reactvideoeditor,
hyperframes.dev) — из одиннадцати таких имён в нашем каталоге нашлось одно
(`notification-stack`). Идеи верные, имена чужие; настоящие аналоги ищутся
через `catalog` по смыслу:

| Что хотели | Что есть на самом деле |
|---|---|
| Aurora Headline | `aurora`, `aurora-drift`, `headline-slam` |
| Prism Lower Third | `lower-third-bild`, `lt-neon-border`, `lt-soft-pill`, `yt-prism-title` и ещё десяток `lt-*` |
| Liquid Counter | `ios26-liquid-glass`, `liquid-glass-widgets`, `count-up`, `number-wheel` |
| Signal Line | `mk-line-graph`, `oscilloscope-trace`, `waveform` |
| Bold Poster | `lt-bold-block`, `vignelli`, `swiss-grid` |

## 5. Тринадцать техник

Это уровень выше отдельных правил — способы, а не рецепты:

рисование SVG-путей; процедурная графика на canvas; трёхмерные CSS-трансформы;
кинетическая типографика по словам; Lottie (экспорт из After Effects, включая
персонажей, которые ходят и жестикулируют); композитинг видео; посимвольная
печать; **анимация осей вариативного шрифта**; движение по траектории
(MotionPath); переходы, согласованные по скорости; анимация, реагирующая на
звук; маски-раскрытия через `clip-path`; фрагментные шейдеры WebGL.

Два полезных частных случая. **Velocity-matched transitions**: входящее
движение подхватывает скорость уходящего — склейка перестаёт читаться как
склейка. **Audio-reactive**: столбики или свечение следуют за звуком;
для озвученного обучающего ролика хватает подсветки ключевых слов по
таймкодам (`asr-keyword-glow`).

### Чем анимировать

GSAP закрывает 95% задач. Lottie — когда у ассета своя готовая временная шкала.
Three.js — трёхмерные сцены и шейдеры. CSS — простые повторяющиеся мотивы без
затрат на JS. WebGPU/TypeGPU — частицы и жидкое стекло. Рантаймы уживаются в
одной композиции: каждый регистрирует свои экземпляры, движок проматывает все
разом.

## 6. Рабочий цикл

```bash
npx hyperframes init <имя> --video файл.mp4 --resolution portrait
npx hyperframes catalog "flowchart" && npx hyperframes add flowchart
npx hyperframes check                        # линт + рантайм + раскладка + контраст
npx hyperframes snapshot --at 1,5,9,13       # кадры + контактный лист
npx hyperframes preview --background         # студия: можно править мышью
npx hyperframes render
```

`check` — не формальность. Он ловит перекрытый текст, провал контраста,
конфликты трансформов и мёртвые зоны. **Ошибка линта выключает проверки
раскладки и контраста**: увидев «0 образцов», не радуйся — просто ничего
не проверялось.

`--resolution`: `landscape` 1920×1080, `portrait` 1080×1920, `square` 1080×1080,
плюс 4K-варианты.

## 7. Грабли, проверенные на себе

**Оверлеи ложатся поверх титров.** У `vignette` `z-index: 90`, у `grain-overlay`
`100`. Текст уходит под них, `check` сообщает `text_occluded`. Титрам нужен
слой выше 100.

**Мерцающее зерно раздувает файл в шестнадцать раз.** Анимация
`steps(1) infinite` меняет каждый пиксель каждый кадр, кодеку нечего
предсказывать: 21 секунда весила 45 МБ вместо 2.8, рендер шёл 2 м 37 с вместо 40 с.
`animation: none` при плотности около 0.07 возвращает 3.5 МБ, и на живописи
статичная фактура честнее читается как холст.

**Перетаскивание мышью в студии оставляет инлайн-сдвиг.** Подложка уехала на
`translate: 8.305px 460.797px` — дробные пиксели выдают случайный драг. Титры
оказались в прозрачной части градиента, и контраст упал до 1.77:1 при норме 3:1.
Снятие сдвига вернуло 15 из 15 проверок.

**Нижние ~300 пикселей вертикального ролика закрыты интерфейсом.** В Reels и
Stories титры надо поднимать, иначе их перекроет подпись и кнопки.

**Размер рендера — индикатор исправности.** Двадцать секунд весом меньше
600 КБ означают, что GSAP не загрузился и видео пустое, хотя рендер отчитался
об успехе.

**Пример `decision-tree` из коробки не рендерится.** `check` проходит, а
рендер падает: `sub_timeline_script_failure`, таймлайн сабкомпозиции не
регистрируется за 45 секунд, в логе `Cannot read properties of undefined
(reading 'hold5')`. Причина — чтение `tl.labels["hold5"]`: при рендере это
поле недоступно. Лечится вычислением момента напрямую:

```js
const hold5Time = tl.duration() + 0.2;
tl.addLabel("hold5", hold5Time);
// дальше вместо tl.labels["hold5"]
const typingStart = hold5Time;
```

Проверено: падает и нетронутый пример, так что дело не в правках. Стоит
проверять другие шаблоны на то же обращение к `tl.labels`.

**Шаблоны не тянут чужой разброс данных.** В `nyt-graph` пределы осей зашиты
константами (`maxRevenue`, `maxConversion`), формат подписей — доллары и
проценты. Подставив свои числа, получишь столбцы, уезжающие за кадр, и
«$157K» вместо «157 с». Править надо и константы, и форматирование подписей,
включая то, что пишется при анимации счётчика.

**Финал шаблона привязан к его длительности.** В `decision-tree` затемнение
стоит на метке `hold7`; растянув ролик под озвучку, получаешь затемнённую
схему за семь секунд до конца, и `check` честно сообщает `text_occluded` по
каждому узлу. Затемнение надо переносить к новому концу.

**Правило «меньше 600 КБ — пустое видео» не работает на плоской графике.**
Схема на белом фоне весит 559 КБ за 10 секунд и при этом совершенно исправна:
кодеку почти нечего кодировать. Порог осмыслен для фото и видео; для
векторных сцен судить надо по кадрам.

**Отдавать стоит два файла:** мастер из `renders/` и лёгкую копию
(`ffmpeg -crf 25 -preset slow -movflags +faststart`) для пересылки.

## 8. Сборка обучающего ролика: порядок

1. **Сценарий и хронометраж.** Текст первичен, картинка под него. Если есть
   озвучка — длительности шотов считаются от длины реплик, а не наоборот.
2. **Выбрать форму шота** из блюпринтов под каждый смысловой блок.
3. **Поставить готовые блоки** из каталога: схема, график, окно кода.
   Руками писать только то, чего в каталоге нет.
4. **Добавить движение** — 2–4 атомарных правила на сцену, не больше.
   Камера живёт микродрейфом, цифры растут вместе со значением, курсор
   нажимает по-настоящему.
5. **Проверить `check`**, посмотреть `snapshot` глазами.
6. **Отрендерить**, сверить размер файла, вынуть кадр из середины.

Два правила, которые экономят больше всего времени: **появление делается
резким** (`set` 0→1), а не плавным фейдом — иначе кадр выглядит вялым; и
**один приём на одну мысль** — два сильных движения в одной сцене гасят друг друга.

## 8а. Планка качества

Рядом лежит `промпт-студии-моушна.md` — готовый стандарт на ролик студийного
уровня. Его числа стоит держать в голове, потому что они проверяемые:

| Что | Норма |
|---|---|
| главный объект в кадре | 60–70% площади |
| главное слово или цифра | от 120 px |
| подписи | не меньше 34 px |
| слов в кадре | не больше пяти |
| отступ важного от края | от 60 px |
| шаг появления слов | ~0,09 с, пунктов ~0,2 с |
| держать итог шага | от 1,2 с, финальную мысль от 2 с |
| выход элемента | вдвое короче входа |

Плюс стоп-лист: текст по центру на градиенте, отскоки, свечение, частицы,
конфетти, эмодзи, стоковые иконки, пустой первый кадр.

### Петля проверки

Черновик в половинном размере → лист кадров через 0,3 с после каждого движения →
оценка каждой сцены от 1 до 10 по пяти осям (понятна ли мысль без звука,
композиция, движение, типографика, ритм) → исправить три худших места →
отрендерить заново. Повторять, пока всё не дотянет до девятки или пока два
круга подряд не перестанут давать прирост. Писать «исправлено» до повторного
рендера нельзя.

Отдельный тест: **сжать кадр до ширины телефона (360 px)** и посмотреть,
читается ли главное.

### Наши ролики против этой планки

Честный замер: в дереве решений самый крупный текст — 32 px, мелкий — 12 px;
в графике 42 и 11. При норме 120 и 34. На ширине телефона подписи узлов и
значения осей **не читаются вовсе** — проверено сжатием кадра.

Вывод не в том, что схемы сделаны плохо, а в том, что **инфографика и ролик
для ленты — разные жанры**. Семь узлов с пояснениями физически не помещаются
в правило «пять слов и 120 px»; такой ролик смотрят с экрана, а не с телефона
в ленте. Если тот же материал нужен для ленты, его надо разбивать: одна ветвь —
одна сцена, по одному решению за раз.

## 8б. Что стоит рядом

**Скиллы GSAP от GreenSock** — `claude plugin marketplace add greensock/gsap-skills`.
Восемь официальных скиллов; для нашего пути полезны `gsap-core`, `gsap-timeline`,
`gsap-utils` и `gsap-performance`. Композиция держится на одном
`gsap.timeline({ paused: true })`, и хореография пишется руками — справочник по
позиционному параметру, вложенности и стаггеру экономит время.
`gsap-react`, `gsap-frameworks` и `gsap-scrolltrigger` не нужны: прокрутки в
рендере нет.

**`browser-use/video-use`** — обработка живой съёмки: вырезает паузы и слова-паразиты,
красит, вжигает субтитры, а оверлеи делает через HyperFrames. Только ffmpeg и pip,
ключей не требует. Закрывает то, чего нет в нашем конвейере: мы умеем собирать
из кадров и генераций, но не чистить запись с речью.

**`calesthio/OpenMontage`** — крупная агентная система, работает «от референса»:
берёт понравившийся ролик и повторяет его структуру. Требует ключей OpenAI и fal.

**`howseen-ai/claude-motion-design`** — тот же принцип, что HyperFrames
(детерминированный `seek(t)`, Chromium и ffmpeg), но с привязкой сцен к битовой
сетке музыки. Пригодится, если понадобятся ролики под трек.

**`remotion`** — React-аналог HyperFrames. Переходить незачем; для переноса чужой
композиции в HyperFrames есть скилл `remotion-to-hyperframes`.

| Нужно | Скилл |
