# Calliope + Claude + MLX

Calliope — локальная студия: хранит проекты, биты, сцены и клипы, ставит задания в
очередь и дёргает ComfyUI по HTTP. Этот плагин закрывает три её слабых места на Mac:
раскадровку пишет Claude по подписке, графы размечаются без ручной возни с JSON,
а сервисы поднимаются одной командой.

## Порядок работы

1. **Проверь, что всё живо** — `scripts/calliope_ctl.py status`. Показывает Calliope,
   ComfyUI, шим и то, какие роли на какой профиль назначены.
2. **Разметь граф**, если его ещё нет в Calliope (см. ниже).
3. **Прогони шот** — `scripts/calliope_ctl.py shot --workflow <id> --prompt "…" --duration 4`,
   затем `job <id> --wait`.
4. **Смотри кадры, а не метаданные.** Совпадение разрешения и числа кадров ничего не
   доказывает: битый прогон выглядит в `ffprobe` нормально. Вынимай кадры через
   `ffmpeg -vf select` и открывай их.

## Разметка графа: главное правило

Calliope не хардкодит номера нод — она читает роли из заголовков нод **API-формата**:
`(Input:prompt)`, `(Input:image)`, `(Output:video)` и т.д. Регистр не важен, есть
алиасы (`face`/`ref` → `character`, `seconds` → `duration`).

**Тег нельзя вешать на произвольную кастомную ноду.** Патчер Calliope пишет одно
значение на ноду, а имя поля выводит из `class_type` по эвристике. Для неизвестного
класса она промахивается мимо настоящего виджета, и значение теряется молча — задание
отработает со старым промптом, и никакой ошибки не будет.

Безопасно тегировать: `LoadImage`, `LoadAudio`, `LoadVideo`, `CLIPTextEncode`,
`SaveVideo`, `SaveImage`, `VHS_*` и любые `Primitive*`.
Для всего остального заводи `PrimitiveStringMultiline` / `PrimitiveInt` /
`PrimitiveFloat`, подключай ссылкой к нужному входу и вешай тег на неё.
Тип обязан совпадать: если вход объявлен `FLOAT`, нужен именно `PrimitiveFloat`.

Несколько `(Input:image)` заполняются **по возрастанию id ноды** — порядок нод решает,
какая картинка станет первым кадром, а какая последним.

```bash
# UI-граф -> API-формат (нужен запущенный ComfyUI: порядок виджетов берётся из /object_info)
python scripts/tag_workflow.py convert мой_граф.json -o мой_граф_API.json
# проставить теги
python scripts/tag_workflow.py tag мой_граф_API.json --set 10=Input:prompt --set 8=Output:video
# проверить глазами, что распозналось
python scripts/tag_workflow.py inspect мой_граф_API.json
# загрузить в Calliope
python scripts/calliope_ctl.py import-workflow мой_граф_API.json --name "Мой граф"
```

После импорта `import-workflow` печатает распознанные слоты. **Пустой список слотов —
это провал разметки**, а не мелочь: граф запустится, но управлять им будет нечем.

Перед импортом прогоняй `comfy validate --workflow <файл>`. Частый улов —
`required_input_missing` на подвходах dynamic-combo вроде `format.codec` у `SaveVideo`.

## Claude вместо локальной модели

`scripts/shim.py` поднимает OpenAI-совместимый сервер, который транслирует
`/v1/chat/completions` в `claude -p`. Работает на подписке Claude Code — **API-ключ
не нужен**. Умеет non-stream, SSE и `response_format: json_object`.

Подключается как обычный профиль LLM: base_url `http://127.0.0.1:8317/v1`,
модель `claude-opus-5`, ключ пустой. Дальше в Settings назначь на него роль `story`
(и `script`, если нужно) — остальные роли могут остаться на локальной модели.

Зачем: на раскадровку qwen3:14b тратит ~10 минут и пишет шаблонно, Claude — около
20 секунд и на языке исходной идеи, сразу операторскими планами.

**Обвес CLI надо срезать**, иначе каждый вызов тащит ~40k токенов системного промпта
Claude Code со схемами инструментов и MCP. Шим уже запускает CLI с
`--system-prompt`, `--exclude-dynamic-system-prompt-sections`, `--strict-mcp-config`
и отключёнными инструментами, и в пустой рабочей директории — иначе подтянется
`CLAUDE.md` текущего проекта.

## Патчи к самой Calliope

В `patches/` лежат четыре диффа к апстриму. Без первых двух назначение роли `story`
просто не работает.

- `agent_llm.patch`, `routers_story.patch`, `agent_script_agent.patch` — роли `story`
  и `script` объявлены в конфиге и настраиваются в интерфейсе, но `generate_structured()`
  создавала клиента **без роли**, то есть всегда на активном профиле. Назначение молча
  игнорировалось. Патчи добавляют параметр `role` и пробрасывают его из вызовов.
- `agent_prompts.patch` — парсер длительности знал только английские единицы. «12 сек»
  не распознавалось, число уходило в ветку «голое число = минуты» → 720 секунд →
  **60 битов вместо 4**; «1 мин» читалось как одну секунду. Добавлены русские формы.

Накладывать из корня `calliope-backend`: `patch -p0 < patches/<файл>.patch`.
После обновления апстрима проверять, не приняты ли эти правки наверху.

## Грабли, на которые легко наступить

- **Обрыв клиента убивает генерацию.** FastAPI отменяет корутину, когда HTTP-клиент
  отвалился по таймауту. Долгие вызовы (раскадровка, рендер) запускать отцепленно,
  а не ждать в `curl`.
- **GET `/api/settings` маскирует `api_key` булевым значением.** Отправить полученный
  объект обратно нельзя — POST падает с 422. Подставляй строку.
- **Бэкенд ставится только через `pip install -e ".[dev]"`.** Один `requirements.txt`
  не кладёт сам пакет (src-layout), запуск падает с `ModuleNotFoundError`.
- **В репозитории Calliope только Windows-скрипты.** `start.sh`/`stop.sh` — в этом плагине.

## Связка с claude-vs-video

`claude-vs-video` пишет шот-лист для роликов Виктории Шворень и по умолчанию отдаёт
продакшн в `claude-video-generate` — то есть в платные агрегаторы. `scripts/vs_bridge.py`
перехватывает этот шаг и отправляет генерацию на локальное железо.

```bash
python scripts/vs_bridge.py parse шотлист.md --root <корень магазина>
python scripts/vs_bridge.py ingest шотлист.md --workflow 1 --project "Название" --root <корень>
python scripts/vs_bridge.py wait <манифест>
python scripts/vs_bridge.py assemble <манифест> -o готовый.mp4
```

Разделение труда такое: реальные фото и видео мост не трогает — по правилу скилла
реальный кадр честнее и дешевле. На рендер уходят только шоты с пометкой
«сгенерировать».

**Ключевые кадры берутся из соседей.** Шот «сгенерировать» получает ближайший
реальный кадр слева как первый и ближайший справа как последний — ровно то, для чего
keyframe-граф и нужен: переход между двумя изображениями. Из видео-соседа берётся
кадр из середины. Если реальный сосед есть только с одной стороны, мост скажет об
этом вслух: переход выйдет вялым, второй кадр стоит задать руками.

Мост сам загружает кадры в ComfyUI через `/upload/image`. Это не лишний шаг:
Calliope умеет загружать файлы, но в рендер-пути этим не пользуется — значение для
`(Input:image)` уходит в `LoadImage.image` как есть, поэтому файл должен уже лежать
в `input` ComfyUI.

Номера нод для кадров задаются флагами `--first-node` / `--last-node` (по умолчанию
4 и 5 — как в `examples/MLX-Keyframe-FLF_API.json`). Для другого графа посмотри
свои номера через `tag_workflow.py inspect`.

Всю цепочку целиком ведёт субагент `vs-pipeline` из плагина `claude-vs-video`:
сценарий и голос — его область, рендер и сборка — наша.

## Форматы площадок

`assemble` знает пресеты: `reels`/`story` (1080×1920), `feed`/`square` (1080×1080),
`portrait` (1080×1350), `site`/`linkedin` (1920×1080).

Титры берутся из колонки «Титр/реплика» шот-листа и рисуются Pillow, а не `drawtext`:
в сборках ffmpeg без libfreetype этого фильтра просто нет, и обычный рецепт с
`drawtext` падает с `Unknown filter`. Отключаются флагом `--no-captions`.

Живопись горизонтальная, поэтому в вертикальных форматах поля по умолчанию
заполняются размытой копией кадра (`--fill blur`). Чёрные полосы (`--fill black`)
съедают половину экрана — для рекламных роликов это прямой удар по досматриваемости.

Какой формат брать под рекламный ролик — решает сценарий, а не сборка: требования
к структуре и площадкам живут в `references/ads.md` скилла `claude-vs-video`.

## Карточки для карусели

`scripts/carousel.py` собирает квадратные карточки из готовых изображений: работа
плюс короткая реплика. Набор описывается JSON-спекой, поэтому тексты правятся без
кода, а пересборка повторяема.

```bash
python scripts/carousel.py build спека.json -o папка/
python scripts/carousel.py preview папка/ -o превью.png
```

Спека: `size`, `root`, список `cards` с полями `image`, `text` (перенос строки —
`\n`), опционально `cta`, `focus_x`, `focus_y`. Абсолютный путь в `image`
берётся как есть — один набор нередко собирается из работ, мокапов и композитов.

**Затемнение под текстом считается по яркости самой работы.** Фиксированная
плотность, которой хватает на тёмном холсте, проваливается на светлом — белый
текст тонет. Проверять надпись нужно в полном размере: в уменьшенном превью
читаемость оценивается неверно.

**`focus_x` решает проблему кадрирования.** На интерьерных снимках картина часто
висит сбоку, и квадратный кадр по центру выбрасывает ровно то, ради чего карточка
делается. Всегда смотри собранные карточки: пустая стена вместо работы —
частая и незаметная в спеке ошибка.

**Проверяй, что работа не продана.** В бэкапе Firestore у каждой есть `status`:
из 50 работ 19 помечены `sold`. Реклама проданной ведёт человека в тупик, а имени
работы на карточке достаточно, чтобы он пошёл её искать. Статус смотреть перед
сборкой, а не после.

Тексты берутся из голоса художницы (`claude-vs-texts` / `claude-vs-video` →
`voice.md`), а не из рекламных формул: стоп-лист запрещает в том числе
«идеально впишется в интерьер» и «гармония и уют».

## Второй бэкенд: fal.ai вместо локального рендера

`scripts/fal_backend.py` считает те же keyframe-переходы на чужих GPU. Подписки нет —
оплата по секундам, ключ берётся из `FAL_KEY` (в окружении или `~/.claude/settings.json`).

```bash
python scripts/fal_backend.py quote шотлист.md --root <корень>
python scripts/fal_backend.py render шотлист.md --root <корень> --manifest m.json --yes
```

**Без `--yes` ничего не запускается** — сначала печатается цена по шотам. Это не
формальность: деньги тратятся на чужом сервисе, и решение принимает человек.

**Минимальная длительность у модели — 6 секунд.** Четырёхсекундный шот считается и
оплачивается как шестисекундный; лишнее обрезается при сборке. Планируя шот-лист под
fal, выгоднее сразу писать длительности из ряда 6, 8, 10, 12, 14, 16, 18, 20.

Кадры уходят как data-URI, уменьшенные до 1920 px — отдельный аплоад в хранилище
не нужен, а исходники до 4000 px только раздували бы запрос.

**Заявка и статус живут по разным адресам.** Отправка — на полный путь модели
(`fal-ai/ltx-2.3/image-to-video/fast`), а статус и результат — по имени приложения
(`fal-ai/ltx-2.3`). На полном пути статус отвечает `405`, и это легко принять за
проблему с ключом.

Манифест получается того же вида, что у локального пути, поэтому
`vs_bridge.py assemble` работает с ним без изменений.

### Чем платить

| | когда | цена |
|---|---|---|
| локально на MLX | черновики, эксперименты | электричество, ~11 мин на 4 с в 512×320 |
| fal.ai | финальные шоты | $0.06/с в 1080p, без подписки |
| Comfy Cloud | свои графы и LoRA в облаке | от $16/мес, кредиты только за активное GPU |

Comfy Cloud **не даёт докупить кредиты на бесплатном тарифе** — сначала подписка.
Для разовых переходов между работами это дороже fal.

## Клонирование голоса и озвучка

`scripts/voice_clone.py` делает голос по образцу и читает им любой текст — через
MiniMax на fal.ai, без подписки.

```bash
python scripts/voice_clone.py clone образец.ogg --name viktoria --yes
python scripts/voice_clone.py say "Текст реплики" --voice viktoria -o out.mp3
python scripts/voice_clone.py say --file сценарий.txt --voice viktoria -o out.mp3
python scripts/voice_clone.py list
```

**Клонировать можно только свой голос или голос того, кто согласился.** Без `--yes`
инструмент не запускается и говорит об этом прямо. Синтез чужой речи без спроса —
подделка личности, а не работа с инструментом; отказывайся, даже если просят.

**Образец — от 10 секунд.** Короче модель не берёт. Opus, m4a и wav приводятся к mp3
автоматически: в нём сервис принимает образцы надёжнее.

**Голос сгорает за 7 дней простоя.** Созданный голос удаляется, если им ни разу не
озвучили текст за неделю, и клонировать придётся заново — за те же деньги. `list`
показывает, сколько осталось. Привязка живёт в
`~/.config/claude-calliope/voices.json`.

**Цена:** клонирование $1.50 разово за голос, превью-текст $0.30 за 1000 символов.
Сама озвучка считается отдельно по длине текста. Для роликов это разумно: голос
делается один раз, дальше платишь只 за реплики.

Параметры озвучки: `--speed` (0.5–2), `--pitch` (-12…12), `--emotion`, `--volume`,
`--sample-rate`. Текст — до 5000 символов за раз.

### Два языка

**Язык определяется по самому тексту** — кириллица читается как русский, латиница
как английский. Задавать `--language` вручную нужно только чтобы переспорить
определитель; модель знает 38 языков, список в `LANGUAGES`.

Для английского автоматически включается нормализация чисел — без неё «80x100»
и «2026» читаются посимвольно.

Пакетный режим озвучивает набор реплик, **каждую на своём языке**: это и есть
обычный случай двуязычного проекта, где половина строк русские, половина английские.

```bash
python scripts/voice_clone.py batch реплики.json --voice viktoria --out озвучка/ --yes
```

Файл — либо JSON со списком `{"id", "text"}` (можно добавить `language`, `emotion`,
`speed` на отдельную реплику), либо обычный текстовый по реплике на строку.
Без `--yes` печатается только разбор: сколько реплик, сколько символов и какой
язык определился у каждой. На выходе — файлы по `id` и `voice-manifest.json`
с длительностями, которым удобно сверяться с хронометражем шот-листа.

Голос для английского отдельно клонировать не нужно — тот же `voice_id` читает
оба языка.
